# DOOV Design System — Color 규칙

이 프로젝트의 모든 UI 색상은 DOOV Design System의 Color 규칙을 따른다.
(KRDS 색상 체계를 참고한 DOOV 전용 체계이며, KRDS 공식 규격과 동일하다고 표기하지 않는다.)

## 1. 디자인 원칙 (가장 중요)
- 화면은 흰 배경 + 쿨 그레이로 구성한다. 포인트 컬러는 DOOV Purple 하나만 사용한다.
- Light 배경은 흰색(--color-bg)이다. 화면 전체를 회색으로 채우지 않는다.
- 연한 보라 등 컬러 배경 면을 만들지 않는다. 로고의 Mint는 로고 전용이며 UI에 쓰지 않는다.
- 주요 버튼: Purple 그라데이션 + 흰 텍스트 (--gradient-primary, --color-text-inverse-static). Light·Dark 공통.
- 보조 버튼: 회색 채움 + 기본 텍스트 (--color-button-secondary-fill, --color-text-basic).
- 선택 상태: 회색 면(--color-action-selected) + Purple 텍스트(--color-text-primary). 세그먼트는 회색 트랙 위 밝은 칸(--color-surface-elevated).
- 상태 표시: 상태색은 아이콘·점·라벨 텍스트에만 쓰고 배경은 회색 면을 유지한다.
- 카드·패널: 흰 표면(--color-surface) + 얇은 테두리(--color-border-light) + 부드러운 그림자(--shadow-sm). 클릭 가능한 카드는 hover 시 translateY(-2px) + --shadow-md.
- 페이지·섹션·히어로 배경은 흰색을 유지한다. 그라데이션은 Purple 계열 토큰만, 하위 요소에만 쓴다: 주요 버튼·아이콘 타일 --gradient-primary, 대형 제목 텍스트 --gradient-text, 카드 내부 배너·일러스트 --gradient-aurora.
- 주요 버튼은 알약형(border-radius 999px) + --gradient-primary + --shadow-primary.
- 헤더는 반투명 유리 질감(배경 72% + backdrop-filter: saturate(180%) blur(20px)).
- 넉넉한 여백과 둥근 모서리(8 / 12 / 16 / 28px)를 사용한다. 표는 세로선 없이 가로 구분선만 사용한다.
- 모션은 cubic-bezier(0.2, 0, 0, 1) 0.2~0.6s로 절제하고, prefers-reduced-motion에서는 끈다.
- 비율: 흰 배경 60 : 쿨 그레이 30 : Purple 10 이하.

## 2. 토큰 구조
- Primitive: --color-primary-{5~95}, --color-gray-{0~100}, --color-{danger|warning|success|information}-{5~95}
- Semantic: --color-bg, --color-bg-subtle, --color-surface, --color-surface-elevated, --color-text-*, --color-border-*, --color-icon-*, --color-button-primary-*, --color-button-secondary-*, --color-action-*, --color-{status}-{icon|text|surface|border}
- 화면 코드에는 반드시 Semantic 토큰만 사용한다. Primitive와 HEX 값을 직접 쓰지 않는다.
- 토큰 원본은 assets/css/tokens.css 이다. 새 프로젝트에는 이 파일을 그대로 복사해 전역 CSS로 등록한다.

## 3. 모드
- Light(기본): :root  /  Dark(검사 화면): <html data-theme="dark">
- 특정 영역만 모드를 바꿀 때는 .theme-light / .theme-dark 클래스를 사용한다.
- 모드별 색은 Semantic 토큰이 자동으로 전환하므로, 컴포넌트에서 모드별 색을 따로 지정하지 않는다.

## 4. 시스템 상태 색 (KRDS 값 사용)
| 요소 | Light | Dark | 토큰 |
|---|---|---|---|
| 아이콘·점 | {status}-50 | {status}-20 | --color-{status}-icon |
| 텍스트 | {status}-60 | {status}-20 | --color-{status}-text |
| 배경 | {status}-5 | {status}-95 | --color-{status}-surface (치명적 경고에만 제한적으로) |
| 보더 | {status}-10 | {status}-90 | --color-{status}-border |

검사 판정 매핑: 적합 = success, 부적합 = danger, 보류 = gray(--color-text-subtle), 주의 = warning
판정 버튼은 회색 채움 버튼에 상태색 텍스트로 표시한다.

## 5. 버튼 상태
- 주요 버튼: fill → hover → pressed = --color-button-primary-fill / -fill-hover / -fill-pressed (점진적으로 진해짐)
- 보조 버튼: --color-button-secondary-fill / -fill-hover / -fill-pressed
- 상태 값에 다른 색조를 섞지 않는다. disabled 상태에 투명도(alpha)를 사용하지 않고 --color-text-disabled 등 토큰을 사용한다.

## 6. 접근성
- 매직넘버: 단계 차이 40 → 3:1, 50 → 4.5:1, 70 → 7:1, 90 → 15:1 이상. 새 색을 추가할 때도 이 규칙을 지킨다.
- 본문 텍스트는 배경 대비 4.5:1 이상, 아이콘·입력창 보더는 3:1 이상(입력창은 --color-border-input).
- 상태 정보는 색상만으로 구분하지 않고 텍스트나 아이콘을 함께 표시한다. (적록 색각이상 고려: 적합/부적합은 반드시 텍스트 병기)
- 배경과 비슷한 5, 95 단계는 텍스트·아이콘에 사용하지 않는다.

## 7. 작업 절차
1. 현재 프로젝트의 색상 정의(CSS 변수, theme, Tailwind config 등)를 먼저 분석한다.
2. 기존 색상 정의와 하드코딩된 HEX/RGB 값을 모두 찾아 이 Semantic 토큰으로 대체한다. 기존 색상 체계를 병행하거나 확장하지 않으며, 대체 후 참조되지 않는 기존 정의는 제거한다.
3. 대규모 변경 전에 영향 범위를 보고하고, 적용 후 라이트·다크 두 모드에서 화면을 검증한다.
4. 기존 기능과 데이터 처리 로직은 변경하지 않는다.

요소기준

그라데이션Purple 계열만 사용합니다. 페이지·섹션·히어로 배경은 흰색을 유지하고, 그라데이션은 주요 버튼, 아이콘 타일, 대형 제목 텍스트 등 하위 요소에만 씁니다.
상태 표시상태색은 아이콘·점·라벨 텍스트에만 사용합니다. 배경은 회색 면을 유지합니다.

Magic Number

매직넘버는 두 색상 단계의 차이로 명도 대비를 보장하는 규칙입니다. 단계 차이만 확인하면 별도 계산 없이 대비 기준 충족 여부를 판단할 수 있습니다.

단계 차이최소 대비적용 예
403 : 1아이콘, 큰 텍스트, UI 구성 요소
504.5 : 1본문 텍스트, 입력창 보더 (예: gray-0 배경 + primary-50)
707 : 1강화 기준(AAA) 본문
9015 : 1고대비 본문

DOOV 팔레트 6종(Primary, Gray, System 4종) 전체에 대해 모든 단계 조합을 검증했으며 위반 사항은 없습니다. 색상을 추가하거나 수정할 때도 이 규칙을 충족해야 합니다.

Modes

Light는 흰 배경의 기본 모드이며, Dark는 검사 화면 등 장시간 영상·이미지를 확인하는 환경에 사용합니다. Dark 배경(gray-95)은 기존 검사 화면의 배경 톤을 기준으로 정의했습니다. 주요 버튼은 두 모드 모두 Purple로 채워 어두운 화면에서도 행동 지점이 분명하게 보이도록 합니다.

Usage

색상 비율

KRDS의 60-30-10 원칙을 DOOV 기준에 맞춰 적용합니다. 60%는 흰 배경, 30%는 쿨 그레이(텍스트·회색 면·보조 버튼), 10% 이하만 Purple입니다.

60 흰 배경
30 쿨 그레이
10 Purple

규칙

  1. 화면 코드에는 시맨틱 토큰만 사용합니다. Primitive 토큰과 HEX 값을 직접 쓰지 않습니다.
  2. 포인트 컬러는 Purple 하나만 사용합니다. 연한 보라 등 컬러 배경 면을 만들지 않고, 묶음은 회색 면으로 표현합니다.
  3. 상호작용 상태(hover, pressed)는 같은 색조 안에서 단계를 점진적으로 올립니다. 상태 값에 다른 색조를 섞지 않습니다.
  4. disabled 상태에 투명도(alpha)를 사용하지 않고 text-disabled, icon-disabled 토큰을 사용합니다.
  5. 배경과 비슷한 5, 95 단계는 텍스트와 아이콘에 사용하지 않습니다.
  6. 본문은 4.5:1, 아이콘과 입력창 보더는 3:1 이상의 대비를 확보합니다.
  7. 팔레트에 없는 새 색상은 재사용성이 높은 경우에만 매직넘버 규칙을 충족하도록 추가합니다.
