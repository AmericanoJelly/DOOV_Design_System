# DOOV Design System — Typography 규칙

이 프로젝트의 모든 UI는 DOOV Design System의 Typography 규칙을 따른다.
코드를 생성하거나 수정할 때 아래 규칙을 반드시 지킨다.
(KRDS의 타이포그래피·가독성·접근성 원칙을 참고한 DOOV 전용 체계이며, KRDS 공식 규격과 동일하다고 표기하지 않는다.)

## 1. 폰트
- font-family: "Pretendard GOV", "Pretendard", "Noto Sans KR", sans-serif
- 로드: https://cdn.jsdelivr.net/gh/orioncactus/pretendard@v1.3.9/dist/web/static/pretendard-gov-dynamic-subset.min.css (SIL OFL 1.1)
- 한글·영문·숫자 모두 동일 서체를 사용한다. 코드 블록만 고정폭 서체를 허용한다.

## 2. 전역 토큰 (전역 CSS 또는 Theme 파일에 등록)
```css
:root {
  --font-family-base: "Pretendard GOV", "Pretendard", "Noto Sans KR", sans-serif;

  --font-size-display: 2rem;       /* 32px */
  --font-size-page-title: 1.5rem;  /* 24px */
  --font-size-section: 1.125rem;   /* 18px */
  --font-size-body: 1rem;          /* 16px */
  --font-size-secondary: 0.875rem; /* 14px */
  --font-size-caption: 0.75rem;    /* 12px */

  --font-weight-regular: 400;
  --font-weight-semibold: 600;
  --font-weight-bold: 700;

  --line-height-display: 1.3;
  --line-height-title: 1.4;
  --line-height-body: 1.5;

  --letter-spacing-default: 0;
}

.typography-display    { font-family: var(--font-family-base); font-size: var(--font-size-display);    font-weight: var(--font-weight-bold);     line-height: var(--line-height-display); }
.typography-page-title { font-family: var(--font-family-base); font-size: var(--font-size-page-title); font-weight: var(--font-weight-bold);     line-height: var(--line-height-title); }
.typography-section    { font-family: var(--font-family-base); font-size: var(--font-size-section);    font-weight: var(--font-weight-semibold); line-height: var(--line-height-title); }
.typography-body       { font-family: var(--font-family-base); font-size: var(--font-size-body);       font-weight: var(--font-weight-regular);  line-height: var(--line-height-body); }
.typography-secondary  { font-family: var(--font-family-base); font-size: var(--font-size-secondary);  font-weight: var(--font-weight-regular);  line-height: var(--line-height-body); }
.typography-caption    { font-family: var(--font-family-base); font-size: var(--font-size-caption);    font-weight: var(--font-weight-regular);  line-height: var(--line-height-body); }
.tabular-nums          { font-variant-numeric: tabular-nums; }
```

## 3. 크기 6단계 (이 외의 크기는 사용 금지)
| Token | Size | Weight | Line Height | 용도 |
|---|---|---|---|---|
| Display | 32px | 700 | 1.3 | KPI 수치, 검사 결과, 주요 지표 |
| Page Title | 24px | 700 | 1.4 | 페이지·대시보드 제목 |
| Section Title | 18px | 600 | 1.4 | 섹션·카드·모달 제목 |
| Body / Primary | 16px | 400 | 1.5 | 본문, 주요 설명, 입력 필드 |
| Body / Secondary | 14px | 400 | 1.5 | 테이블, 버튼, 보조 설명 |
| Caption | 12px | 400 | 1.5 | 도움말, 단위, 부가 정보 |

## 4. 굵기 3단계
- 400 / 600 / 700만 사용한다. (100, 300, 500, 800 등 사용 금지)
- 강조가 필요하면 크기를 바꾸지 말고 굵기만 바꾼다.

## 5. 컴포넌트별 규격
| 컴포넌트 | Size / Weight |
|---|---|
| KPI 핵심 수치 | 32 / 700 |
| 페이지 제목 | 24 / 700 |
| 섹션·카드·모달 제목 | 18 / 600 |
| 기본 본문, 입력 필드 | 16 / 400 |
| 강조 본문, 메인 메뉴 | 16 / 600 |
| 서브 메뉴, 표 데이터, 보조 설명 | 14 / 400 |
| 표 헤더, 버튼, 상태 배지 | 14 / 600 |
| 캡션, 도움말 | 12 / 400 |

## 6. 작성 규칙
- font-size, font-weight, line-height를 px나 숫자로 직접 쓰지 않는다. 반드시 var(--font-*) 토큰 또는 .typography-* 클래스를 사용한다.
- letter-spacing은 0을 유지한다.
- 수치 데이터에는 tabular-nums를 적용하고, 표의 수치 열은 우측 정렬한다.
- 정상/불량 등 상태는 색상만으로 구분하지 않고 텍스트를 함께 표시한다.
- 중요한 상태 정보와 오류 메시지는 12px로 표시하지 않는다.
- 일반 텍스트는 배경 대비 4.5:1 이상을 확보한다.
- html의 font-size를 px로 고정하지 않고, user-scalable=no 등 확대를 막는 설정을 쓰지 않는다.
- 고정 높이 대신 패딩과 행간으로 영역을 잡아 200% 확대 시에도 잘림이나 겹침이 없게 한다.
- Tailwind, CSS Modules, styled-components 등을 사용하면 같은 토큰 값을 해당 theme 설정에 매핑한다.

## 7. 작업 절차
1. 현재 프로젝트의 프레임워크, 스타일링 구조, 기존 폰트 설정을 먼저 분석한다.
2. 기존 Typography 스타일, 폰트 설정, 중복 CSS를 모두 찾아 이 토큰으로 대체한다. 기존 디자인 시스템에 타이포그래피 정의가 있어도 병행하거나 확장하지 않고 이 규칙으로 대체하며, 대체 후 더 이상 참조되지 않는 기존 정의는 제거한다.
3. 버튼, 입력 필드, 테이블, 메뉴, 카드, 모달 등 공통 컴포넌트부터 적용한다.
4. 대규모 변경 전에 영향 범위를 정리해 보고하고, 적용 후 레이아웃이 깨지지 않았는지 검증한다.
5. 기존 기능과 데이터 처리 로직은 변경하지 않는다.

Purpose

  • 일관성 — 동일한 UI 요소는 모든 화면에서 동일한 크기와 굵기로 표시합니다.
  • 가독성 — 고밀도 데이터 화면에서도 정보의 위계가 명확하게 인지되도록 합니다.
  • 유지보수성 — 폰트 규격을 개별 화면에 하드코딩하지 않고 토큰으로 관리하여, 토큰 수정만으로 전체 UI에 반영합니다.

본 체계는 KRDS(Korea Design System)의 타이포그래피, 가독성, 웹 접근성 원칙을 참고하여 DOOV 환경에 맞게 정의한 DOOV 전용 기준이며, KRDS 공식 규격과 동일하지 않습니다.

Tokens

전역 토큰은 assets/css/tokens.css에 정의되어 있으며, rem 값은 루트 16px 기준입니다.

:root {
  /* FONT FAMILY */
  --font-family-base: "Pretendard GOV", "Pretendard", "Noto Sans KR", sans-serif;

  /* FONT SIZE */
  --font-size-display: 2rem;       /* 32px */
  --font-size-page-title: 1.5rem;  /* 24px */
  --font-size-section: 1.125rem;   /* 18px */
  --font-size-body: 1rem;          /* 16px */
  --font-size-secondary: 0.875rem; /* 14px */
  --font-size-caption: 0.75rem;    /* 12px */

  /* FONT WEIGHT */
  --font-weight-regular: 400;
  --font-weight-semibold: 600;
  --font-weight-bold: 700;

  /* LINE HEIGHT */
  --line-height-display: 1.3;
  --line-height-title: 1.4;
  --line-height-body: 1.5;

  /* LETTER SPACING */
  --letter-spacing-default: 0;
}

Accessibility

  • 모든 크기는 rem 단위로 정의하며, html의 font-size를 px로 고정하지 않습니다. 사용자의 브라우저 글자 크기 설정과 확대 기능을 제한하지 않습니다.
  • user-scalable=no, maximum-scale 등 확대를 차단하는 viewport 설정을 사용하지 않습니다.
  • 일반 텍스트는 배경 대비 4.5:1 이상의 명도 대비를 확보합니다.
  • 200% 확대 시에도 텍스트 잘림이나 겹침이 발생하지 않도록 고정 높이 대신 패딩과 행간으로 영역을 확보합니다.
  • 정상/불량 등 상태 정보는 색상만으로 구분하지 않고 반드시 텍스트를 함께 표시합니다.
  • 중요한 상태 정보와 오류 메시지는 Caption(12px)으로 표시하지 않습니다.

Rules

신규 화면 및 컴포넌트 개발 시 아래 기준을 준수합니다.

  1. 폰트 크기, 굵기, 행간은 반드시 토큰(var(--font-size-*) 등) 또는 .typography-* 클래스로 지정합니다. px 값을 직접 작성하지 않습니다.
  2. 6단계 외의 폰트 크기를 추가하지 않습니다. 강조가 필요하면 굵기를 변경합니다.
  3. 굵기는 400 / 600 / 700만 사용합니다.
  4. 동일한 UI 요소는 Component Mapping의 규격을 그대로 따릅니다.
  5. 검사 결과, 생산량, 불량률 등 주요 KPI는 Display(32px)를 적용합니다.
  6. 수치 데이터에는 tabular-nums를 적용합니다.
  7. 현장 원거리 확인 등 예외 규격이 필요한 경우 임의로 확대하지 않고, 디자인 시스템 담당자 검토 후 토큰으로 추가합니다.
